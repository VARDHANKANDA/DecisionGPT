# Protocol amendments (append-only; the frozen `EXPERIMENT_PROTOCOL.md` is not edited)

## Amendment 1 — 2026-10-22, before any E-COST result was inspected beyond the first 10 records' determinism check
Reading `backend/app/evaluation/harness.py` and `ground_truth.score_selection` showed that condition A (prediction only) recommends nothing and is **scored as the status-quo / minimal-intervention action**: the no-op if it is in the decision set, otherwise the smallest-magnitude feasible action (`ground_truth._noop_action`). In most locked scenarios the no-op is not in the decision set, so A is scored as the smallest feasible change (e.g. `price_change=-3`). §0 of the protocol ("recommends nothing") is therefore read as "recommends nothing; scored as the minimal-intervention reference". The paper must say this wherever A is compared; A is a reference, not a decision-support architecture.
Effect on analyses: none (the stored regrets are used as stored).

## Amendment 2 — 2026-10-22, before the full E-COST run was completed
The first 40 instances of a first launch of `cost_measurement.py` (which counted simulator calls but did not time the time spent inside the simulator) were set aside, unanalysed beyond a plausibility check, as `logs/pilot_v0_first40_instances_without_sim_timing.jsonl`; the script was extended to also record `sim_seconds_by_phase` (time inside `digital_twin_service.simulate_strategy`, by calling phase) so that the **orchestration overhead of D = D pipeline time − time D spends in its own simulations** can be reported next to the end-to-end ratio. The plausibility check had shown D/B ≈ 1.1 with large run-to-run noise, which motivated the extra quantity (post-hoc, disclosed). The pilot rows are not used in any result. The measurement was restarted from scratch.
