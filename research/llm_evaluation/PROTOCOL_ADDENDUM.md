# Addendum to `research/LLM_EVALUATION_PROTOCOL.md` — POS objective analytics Q&A track

The locked protocol is **not edited**. This addendum records how this first evaluation uses it.

1. **Dataset selected (the protocol required one to be named before execution):** `data/external/india_pos_register/` — Indian POS register, 1 Jan–31 Mar 2025, real by file evidence, provenance unverified, CC BY-NC-SA 4.0, not representative of Indian SMEs. Disclosed in every report.
2. **Why an objective chat track exists:** the protocol says free-form chat has no objective ground truth *in general*. Descriptive analytics questions over a transactional table do have exactly computable answers; only those are used here. No claim is made about open-ended chat, recommendations or decisions.
3. **Mapping to protocol baselines:** B5 = DecisionGPT `POST /chat` (production path). B2 = LLM + read-only data tool (this track's baseline). B1 (LLM-only with the data in the prompt) is **not run**: the view has 30,293 rows (about 1.1 million characters, roughly 280k tokens by a rule of thumb), beyond most context windows. B0/B3/B4 are not applicable to this question type.
4. **Repeats:** 5 independent calls per task (protocol recommendation), fixed in the spec before any run; temperature 0 is hard-coded in `llm_provider.py` and no seed is supported.
5. **Metrics:** objective scoring only (accuracy with pre-set tolerances, numeric error, ranking correctness, failure rates, latency, tokens, cost where returned). The human rubric of the protocol is not used because every task here has deterministic ground truth.
6. **Execution status:** BLOCKED until `LLM_PROVIDER`, `LLM_API_KEY` and `LLM_MODEL` point at a real provider.
7. **Update 2026-10-08 (evaluation target):** item 3's mapping "B5 = DecisionGPT `POST /chat`" is accurate but B5 is a deterministic router/template system, not an LLM-powered one (see `ARCHITECTURE_AUDIT_2026-10-08.md`). Execution status is now **BLOCKED - production path not LLM-powered** (plus, separately, provider not configured). The tool-use system is a capability reference, not a simpler baseline. The locked protocol is still not edited.
8. **Update 2026-10-08 (later, supersedes item 7's execution status):** the production chat now contains an LLM analytics path (question -> LLM interpreter -> validated structured request -> deterministic query engine -> verified result -> grounded answer), so the system under test is that path (Target B) and B5 is no longer only a router. Execution is blocked **only** by the absent LLM provider. Because the engine, not the model, produces every number, the evaluation of this path measures question understanding / request construction and end-to-end behaviour, and must be reported as such; the pandas tool-use system remains a capability reference. The locked protocol is still not edited.
9. **Update 2026-10-08 (readiness gate):** a single user question normally needs **two** LLM calls (interpreter, then explainer); the experiment reports calls per task, interpreter / engine / explanation / end-to-end latency, tokens per role and in total, and cost only when verifiable. The scientific boundary is fixed: the deterministic query engine is the numerical authority; the evaluated component is the natural-language-to-structured-analytics interpretation layer (with the second call only explaining verified results). It does not evaluate arithmetic, causal reasoning, profit/churn prediction, pricing or marketing optimisation, business outcomes, human decision quality or SME representativeness. Fallbacks are not LLM successes; GST refusals are an unsupported supplementary track. The first real run must start from this frozen state: no prompt, schema or task changes.
10. **Update 2026-10-13 (provider migration, before any model was executed):** the provider is TypeSafe AI Jev (typed decisions only; no text, no code). The evaluated component is the typed classification of the question together with deterministic value extraction; there is no explainer call and no retry; the pandas tool-use reference system cannot run on Jev (B2 is therefore not executable with this provider). Repeats, tasks, tolerances, scorer, ground truth and manifest are unchanged. The locked protocol is still not edited; see `DEVIATIONS.md` entry 8.
11. **Update 2026-10-14 (first live run, partial pilot):** 6 frozen tasks x 1 repeat, one task per category by lowest frozen task id, selected and recorded before the run; hard request cap 6; condition `asof`; no retries. The frozen protocol (27 tasks x 5 repeats) was NOT executed and its results are not claimed. See `DEVIATIONS.md` entry 9 and `pilots/pilot_2026-10-14_selection.json`.
12. **Update 2026-10-14 (stage 2, second partial run):** the 21 tasks not in the pilot, 1 repeat, condition `asof`, request cap 21, selection pre-registered in `pilots/stage2_PROPOSAL_not_executed.json`. Frozen protocol (27 tasks x 5 repeats) still NOT executed. See `DEVIATIONS.md` entry 10.
13. **Update 2026-10-14 (provider migration to OpenAI):** new runs use OpenAI (`openai` SDK, Responses API, strict JSON schema). Tasks, tolerances, scorer, ground truth, repeats and manifest are unchanged. Request count per attempt can be 2 (classification + validated restatement); a hard request cap is mandatory for any run. Jev and OpenAI results are separate records and are never pooled. See `DEVIATIONS.md` entry 11.

Frozen protocol (27 x 5) not executed. See `DEVIATIONS.md` entry 12 and `pilots/openai_smoke_EXECUTED_run_20261014T172246Z_f320dc9f.json`.

The smoke run did not have them. Frozen protocol (27 x 5) not executed. See `DEVIATIONS.md` entry 13.
