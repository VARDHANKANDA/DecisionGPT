## 2. Commands (run from the repository root; `PYTHONPATH=.`)

```bash
python -m pytest tests/unit/test_forecast_study_v2.py -q                       # unit tests
python -m research.forecast_study_v2.simulation                                  # inference simulation (synthetic; ~12 min)
python -m research.forecast_study_v2.tools.data_audit                            # dataset/window properties (raw files)
python -m research.forecast_study_v2.tools.independent_targets_check             # targets rebuilt from raw
python -m research.forecast_study_v2.freeze verify                               # frozen protocol/code hashes
PY=python bash research/forecast_study_v2/run_v2.sh validation                   # stage 1: ~1 h
PY=python bash research/forecast_study_v2/run_v2.sh test                         # stage 2: refuses to run unless the freeze verifies; ~1.5 h
python -m research.forecast_study_v2.report                                      # analysis, tables, figures
python research/forecast_study_v2/verify_independent.py W2 W3 W1                 # independent verification (imports nothing from the study)
python -m research.forecast_study_v2.report_extra                                # verdict counts, design effects
python -m research.forecast_study_v2.supplementary_h3                            # supplementary H3 precision check (~6 min)
python research/forecast_study_v2/tools/build_tables.py                          # manuscript tables from stored artifacts
python research/forecast_study_v2/tools/assemble_manuscript_r2.py                # MANUSCRIPT_R2.md
python research/forecast_study_v2/tools/check_numbers.py                         # numeric consistency of the manuscript (49 checks)
```

Interrupted runs resume from `fits/*.npy` when the configuration hash in `config.json` is unchanged; otherwise the run refuses to start. The `PY` variable selects the interpreter (the reported runs used the repository's `backend/.venv`).

## 3. Outputs and where each number comes from

`results/<window>/<dataset>_H<H>/`: `config.json` (candidates, features, blocks, hashes), `selection.json` (validation-only selection, leakage checks), `fits/*.npy` (every model fit's predictions), `predictions.npz` (targets, selected models, baselines, seed refits), `results.json` (endpoints, ladder, segments), `metadata.json` (versions, code hashes, freeze hash); `results/analysis/analysis_<window>.json`; `results/verification/…`; `METRIC_RESULTS.csv`, `MODEL_COMPARISON.csv`, `results/TABLES.md`, `figures/*.svg` are generated by `report.py` from those files. **`predictions.npz` contain actual M5 sales and must not be published** (data rights).

## 4. Determinism and known sources of nondeterminism

Seeds: model 42 (43, 44 for sensitivity), bootstrap 20261024, simulation 20261023, M5 series draw 20261015. LightGBM: `deterministic=True`, `force_row_wise=True`, 4 threads; XGBoost `hist`. Results may differ in the last digits across thread counts, library versions and operating systems (the v1 historical re-run showed differences of up to 1.5e-5 for a random forest). The M5 series draw and all splits are deterministic. Re-running on this machine with the same settings is expected to reproduce all numbers to many decimals **[not performed beyond the cached resumptions]**.

## 5. Software quality and validity

Unit tests (`tests/unit/test_forecast_study_v2.py`) check leak-freedom of the baselines (overwriting everything after the cutoff does not change any of 16 estimators in either information set), metric identities, objective semantics (the absolute-error and quantile objectives recover the median of a skewed sample, squared error the mean), window arithmetic, truncation and the Online Retail II SKU re-selection (recomputed from raw transactions), and the inference helpers. **Passing tests show that the code behaves as written; they do not show that the design answers the research question or that the conclusions are valid.** The independent verification layer (`verify_independent.py`) is a separate, stronger check but was written by the same AI assistant as the study (see `FINAL_VERIFICATION_REPORT.md`).

## 6. Clean-environment reproduction and portability

Performed 2026-10-22 (**[done], partial**): a fresh Python 3.12.0 virtual environment was created outside the repository and `requirements.txt` installed from PyPI; the resolved versions of the ten pinned packages are identical to `environment_freeze.txt`. In it (i) the 17 study unit tests pass (`--noconftest`, because the repository-level `tests/conftest.py` needs the backend's FastAPI stack, which is not part of this study's requirements); (ii) one complete cell — Online Retail II, window W2, H = 7, validation stage, test stage and both extra seeds, 61 s — was re-run into a scratch directory with the frozen-protocol check active: selection (item-day model `lgbm_l1_small`, subset-day model `lgbm_tweedie_p11`, baseline `matched__weekday_median8`) and all 35 stored method summaries reproduce with a maximum absolute difference of **0** in item-day WAPE, subset-day WAPE and relative bias.
**Not performed:** a clean-environment re-run of the other 21 cells (about 2.5 h of CPU), re-running on a different operating system or CPU count, and re-obtaining the raw data. The claim is therefore "one cell reproduced exactly in a fresh environment with identical pinned versions", not a full clean-room reproduction. The repository's historical modules (`ml.benchmark.*`) are imported from the working tree; raw data must be obtained by the user; `run_v2.sh` needs bash.

## 7. Failure and recovery

If a run stops: re-run the same command (completed fits are reused). If `freeze verify` fails, a frozen file changed — restore it or record a dated deviation in `DEVIATIONS.md` before any test-stage run. If a feature leakage check fails the stage aborts. A cell whose configuration hash changed must be moved aside (never deleted) before re-running.
